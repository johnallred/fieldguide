    Generated page

    This page is generated from concepts.yaml and demonstrations.yaml by fieldguide build. Edits here are overwritten. Change those files instead.

    This guide is prose about how to do a job, and prose is cheap. This page records which concepts are also implemented somewhere you can open, down to the file that does the work.

    77 of 106 concepts have a demonstration, 37 of them in full. The rest of this page is the other side of that number, which is the half worth reading.

    docpack¶

    Turns a documentation tree into retrieval-ready, agent-readable artifacts.

    A Python library and the documentation site that documents it, where the site is also the test corpus. Ten CI gates, 142 tests, a 20-case retrieval evaluation, an MCP server, and a cold-start harness that follows the quickstart from an empty virtual environment.

    https://github.com/johnallred/docpack · demonstrates 49 concepts

    fieldguide¶

    This guide, which validates its own curriculum and its own pages.

    The repository you are reading. It earns entries here only where it does the work rather than describing it: a two-part fence gate that compares fenced source against the rendered code blocks of the built HTML, and an accessibility property test over generated pages. The fence gate found 127 defects across seven pages that every other check had passed.

    https://github.com/johnallred/fieldguide · demonstrates 35 concepts

    What is demonstrated¶

    full means the concept is implemented as this guide describes it. partial means something real is there and the concept page asks for more, and it is used literally: rag is partial because the records are retrieval-ready and nothing embeds them.

    Vector stores and hybrid search partial drills/vector_store.py An IVF index over 4000 hashed vectors in 64 dimensions, measuring what an approximate search costs: 0.548 recall@10 probing one cluster of 64, 0.988 probing eight while scanning 13% of the corpus, and slower than brute force past the knee. The vectors are hashed rather than learned, which preserves the recall and latency geometry exactly and preserves nothing about semantics, so the drill also measures what it cannot show and the page tabulates the boundary.

Committing it found the page had quoted no output at all, that five defects yield ten findings, and that the word-count check false-positives on a sixteen-word static page. No real site, no crawler, no search engine.
    Hallucination and guardrails partial drills/guardrails.py Four guardrail layers run against eight fluent answers, six of them wrong, producing the matrix of which layer catches which failure. The result worth having is a negative one: grounding passes a fabricated flag name as soon as real text surrounds it, so only a known-identifier list catches the convincing fabrications. No model, no retrieval and no live pipeline; the answers are written by hand to isolate the failure modes.
    SEO for documentation full hooks/seo.py Per-page meta description from the content model's summary, plus a CI step that fails if the hook is ever unregistered.
    Structured data and JSON-LD full hooks/seo.py Open Graph, Twitter cards and JSON-LD, all derived from one required field rather than hand-written per page.

    Developer education and curriculum¶

    8 of 8.

    Concept Extent Artifact What it does
    Cognitive load in technical content partial src/fieldguide/audit.py Sentence distribution, per-page maxima and the backward/forward/off-path link census, committed as a subcommand with a test fixture for each of the three fence-parsing bugs that preceded it. The loop is now closed rather than open: the corpus was measured, 59 pages carried a sentence over 45 words and six over 60, the worst were edited, and a test holds the ceiling at 55 so it cannot drift back. Two defects fell out of acting on it. The splitter did not treat a sentence ending in bold as a sentence ending, which accounted for as much of the improvement as the editing did, and the metric excluded list items, so a long sentence became compliant the moment somebody bulleted it; both are fixed and both are published beside the result. The effect on a reader is still unmeasured. Ceiling: no-audience.
    Instructional design for developers partial src/fieldguide/audit.py fieldguide audit prints the four structural commitments on demand: 89/89 prerequisite lines, 106/106 durations, results and proof sections. Since then the commitments became enforceable rather than measurable: STRUCTURAL_LABELS declares the wording of all fourteen labelled elements, the scaffold emits them so a new page cannot invent a fifteenth, and the audit reports every repeated label nobody declared. That last check is the one that matters, because this page's own fix had standardised the label that surfaced and asserted that one string, which could not have found the three other variant pairs in use at the time. Ceiling: no-audience.
    Learning paths and curriculum partial src/fieldguide/generate.py Seven paths generated from the registry, ordering enforced in CI, entry state computed; no reader has walked one.
    Assessment and checks for understanding partial src/fieldguide/audit.py 318 proof tasks measured across 106 pages, 95 per cent imperative and 40 per cent stating a success criterion. That second figure was published as 17 per cent for months and the classifier was wrong: it matched the preposition in "run it against a corpus you own" and recognised no conditional, predicted value or author comparison, so the guide's self-declared weakest number was about half the real one. It is now scored against sixty tasks hand-labelled before it was written, held in tests/fixtures/criterion_labels.json. The 40 is after a pass that added a criterion to every core page that had none; the correction was worth more than the pass. It establishes that the instrument is well formed and nothing about whether anyone learns. Ceiling: no-audience.
    Developer advocacy partial tests/test_registry.py A docs gate at capability granularity, enumerating subcommands from the parser; the partnership half is undemonstrable in a one-person repository.
    Publishing in public partial scripts/prepublication.py A pre-publication gate at full precision on two repositories; neither is published, so there is no audience yet.
    Workshops and hands-on labs partial drills/workshop_arithmetic.py The arithmetic that decides what a workshop can cover, computed from the registry rather than quoted: a ten-concept path's hours, the share of it two hands-on hours buys, and how many concepts are short enough for one sitting. It found the page calling a thirty-four-hour path the shortest when a twenty-four-hour one existed. No room, no attendees, and the setup timings on that page remain one unverified run.
    Screencasts and video partial drills/screencast_script.py A screencast script treated as a testable artifact: a beat that was never true, a clean pass once the tool gains the flag the narration promised, and the same script going stale when upstream rewords one line. Reports drift by timestamp, which is what makes a stale recording actionable. No camera, no voice, no edit.

    Why the gaps are there¶

    Every concept with no demonstration carries a recorded reason, and the build fails on a concept that has neither. So this is a decision register rather than a list of things nobody got to.

    Reason Concepts What it means
    declined 7 demonstrating it would mean adopting a tool or process this project does not need

    What is demonstrated as far as it can be¶

    A gap closes when somebody does the work. A ceiling does not, and the difference is worth publishing: these concepts have a working mechanism and a stated reason why no amount of further code reaches full.

    Reason Concepts Why it stops there
    no-audience 9 the corpus-side half is built and measured; the reader-side half needs readers, and this project has none
    not-published 2 the mechanism runs and gates, but nothing is deployed, so no post-publication behaviour exists to observe

    no-audience: Assessment and checks for understanding, Cognitive load in technical content, Turning developer feedback into changes, Documentation analytics, Instructional design for developers, Learning paths and curriculum, Reproducible environments, Sample applications and galleries, Time to first success

    not-published: Publishing in public, Release readiness for documentation

    A portfolio that published only the first table would be the flattering half of the truth. The gaps are where the interview happens.
